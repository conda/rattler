2//! Discovery, retrieval and verification of Sigstore attestations for conda
3//! packages.
4//!
5//! This crate implements the client side of two conda CEPs:
6//! [CEP 50](https://conda.org/learn/ceps/cep-0050), which standardizes how
7//! Sigstore attestations are distributed alongside packages, and
8//! [CEP 27](https://conda.org/learn/ceps/cep-0027), which standardizes the
9//! attestation format and the rules for verifying one. CEP 50 adds no
10//! publish-attestation verification rules of its own.
11//!
12//! - A package record advertises its attestations through the
13//!   `attestations_sha256` field of the repodata (CEP 50).
14//! - The attestations live in a sidecar at `<package_url>.sigs.<sha256>`, a
15//!   JSON array of Sigstore bundles (CEP 50). See [`sidecar`].
16//! - Each bundle is verified with `sigstore-verify` against the package's
17//!   SHA256 and then checked against the CEP 27 rules for conda publish
18//!   attestations. See [`verify`].
19//! - A [`VerificationPolicy`] decides which signing identities are trusted for
20//!   all packages and whether failures warn or block. Neither CEP prescribes
21//!   this; CEP 50 leaves trust policy explicitly out of scope. See [`policy`].
22//!
23//! # Example
24//!
25//! ```no_run
26//! use rattler_sigstore::{Issuer, Publisher, VerificationConfig, VerificationPolicy};
27//!
28//! # async fn example(record: rattler_conda_types::RepoDataRecord, client: reqwest_middleware::ClientWithMiddleware) -> Result<(), rattler_sigstore::SigstoreError> {
29//! let config = VerificationConfig::new(
30//!     Publisher::new()
31//!         .with_identity("https://github.com/my-org/*")
32//!         .with_issuer(Issuer::github_actions()),
33//! );
34//! let policy = VerificationPolicy::Require(config);
35//!
36//! let outcome = rattler_sigstore::verify_record(&policy, &record, &client).await?;
37//! assert!(outcome.is_verified());
38//! # Ok(())
39//! # }
40//! ```
